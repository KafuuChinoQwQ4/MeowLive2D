# MeowLive2D

让 Live2D 角色用你选择的声音说话，并由 AI 回应观众的弹幕和礼物。

你可以先输入文字试播，再接入 AI 和直播间；想进一步调整声音时，也可以训练自己的音色。**上传参考录音就能试播，不必先训练。**

项目仍在开发，暂无安装包。Windows 负责播放声音和运行 VTube Studio，Linux / WSL 负责 AI 和语音服务。第一次使用，请先按 [启动说明](launchers/README.md) 准备环境。

## 先播报一句话

1. Windows 双击 `launchers/start-windows.cmd`；或在 Linux / WSL 项目目录运行：

   ```bash
   ./launchers/start.sh
   ```

2. 打开控制面板：<http://127.0.0.1:1420>。保持启动窗口开启。
3. 在 **环境与模型** 选择已有的 GPT-SoVITS v2 语音模型，或下载后选择。其他标记为“需适配”的模型暂不能使用。
4. 在 **启动与运行** 依次开启 **主服务 → TTS 语音引擎 → Windows 执行端**，等待服务就绪、执行端已连接。TTS 就是把文字变成声音的服务。服务就绪后，在 **训练与离线** 点击 **启用语音模型**；首次加载可能需要几分钟。
5. 在 **角色与音色** 上传一段 3～10 秒的清晰录音，填写录音对应的文字，保存并设为当前音色。支持 MP3、WAV 等常见格式。
6. 到 **语音播报** 输入“你好，欢迎来到直播间”，点击播报，确认能听到声音。

## 让模型跟着声音动嘴

打开 VTube Studio（简称 VTS），加载模型，开启插件 API，并允许 MeowLive2D 连接。

在 VTS 的模型设置中找到嘴部开合那一项，将 **IN（输入）** 改为 `MeowMouthOpen`，输入范围设为 `0～1`。**OUT（输出）** 选择模型的嘴部开合参数，通常叫 `ParamMouthOpenY`；标准模型的输出范围也是 `0～1`。

再播报一句话，确认有声时动嘴、结束后闭嘴。更多参数见 [配置说明](config/README.md)。

## 让 AI 回应观众

1. 打开 **LLM 接入**，填写大模型服务的 API 地址、模型名称和密钥，测试连接后保存。
2. 在 **启动与运行** 关闭并重新打开主服务，再重新开启 Windows 执行端，使配置生效。
3. 进入 **Agent 互动**，填写主播人设和话题，保存后点击 **恢复 Agent**。
4. 在同页发送一条模拟聊天，例如“介绍一下自己”，确认 AI 能生成回复并说出来。

Agent 是负责自动互动的 AI。人设、话题、冷却时间及主动发言选项点击“保存设置并暂停”后会记录在本机，关闭面板或重启主服务后仍保留。它默认暂停；保存设置或连接断开后，需要手动恢复。想让它在没有弹幕时自己聊天，可勾选“允许空闲时主动发言”。

**连接真实直播间：** 当前支持 B 站官方直播开放平台。在 **直播连接** 页填写应用 ID、AccessKey ID、AccessKey Secret 和主播身份码，启用并保存后即可点击“连接直播间”，再恢复 Agent。设置保存在本机，下次启动自动读取，不需要编辑配置文件或环境变量；单填房间号不能接入。OBS 地址和密码在 **OBS 场景与录制** 页填写保存。正式直播时，用 OBS 采集 VTS 画面和播放的声音。

## 观众档案与持久事件

控制面板用户默认拥有管理权限，无需另行登录管理员。PostgreSQL 默认保存观众身份、昵称历史、直播事件、陪伴积分和记忆；重复事件在服务重启后仍会去重。开启主服务时会自动准备本项目 PostgreSQL（需要 Docker），随后可直接进入“观众记录”管理。配置步骤见 [配置说明](config/README.md#启用观众档案与持久事件)。观众详情还提供陪伴积分与礼物依据、短期/长期记忆证据、关系图，以及有预览和确认的身份合并。后台记忆模型与 Neo4j 按需独立启用；资料删除会取消旧上下文生成和待播内容，完成回执使用本地持久日志跨重启恢复。详见 [陪伴、记忆与图谱配置](config/README.md#陪伴记忆与图谱) 和 [数据恢复说明](config/viewer-recovery.md)。当前已验证模拟模型和执行端配合真实数据库的链路；真实直播金额、提取质量及 Windows 播放需实机验收。

## 想进一步训练声音

训练是可选步骤，和日常播报分开进行。**训练前关闭语音模型，训练完成后再启用模型试听；受管 TTS 服务可以保持开启。**

1. 在 **训练与离线 → 新建训练** 选择本次训练的音色，填写训练名称。
2. 上传同一个人的 2～32 段录音，每段 3～10 秒。原文件每段不超过 20 MiB，总量不超过 32 MiB。
3. 已配置本地语音识别模型时，可以自动提取文字；没有时，勾选“输入并校对文本”，逐片填写并确认。
4. 选择省内存、均衡或高吞吐预设，也可展开高级参数调整。结束直播，点击“关闭语音模型”并停止本地大模型推理，释放显存后开始训练。
5. 到 **训练记录** 查看进度；完成后启用语音模型，到 **已训练音色** 试听新版本，确认后保存，再点击“使用所选音色”。

显示 **“训练未配置”**，表示还没有启用训练引擎；设置当前音色不会自动启用它。需要按 [配置说明](config/README.md) 填写训练环境并重启主服务。

片段、训练记录和已训练音色每页最多显示 5 条；已训练音色按参考音色归组，同一音色的版本在卡片中展开选择，切换页签会保留当前训练草稿。轮次、性能参数、文本模式及试听文本自动保存在当前浏览器，按主服务地址区分，下次打开会恢复；清除浏览器数据会清除这些偏好，素材和校对确认仍需重新选择。模型开关独立于 TTS 服务，关闭会卸载推理权重和相关缓存，已保存的权重文件和音色选择仍保留；需要播报或试听时再启用。它控制推理模型驻留，正在训练的任务仍使用原有的取消操作。

不同训练预设会调整批大小、数据加载进程和 CPU 线程；高级设置还支持 GPU 编号和低显存优化。参数越大不一定越快，也会增加内存需求。这次新增选项未做真实训练或硬件速度验证。

想训练两个人的声音，就分别创建两个音色、使用各自的录音。同一音色后续训练会接着最近一次成功版本的 GPT / SoVITS 权重继续学习新素材；没有成功版本时使用通用预训练模型。每次训练仍保存独立版本，可试听、切换和删除单个版本，不会覆盖旧权重。旧的独立训练结果只归入同一音色管理，不直接混合权重；续训也不保证声音效果每次都会提升。

控制面板的成功与进度提示直接显示在页面内，服务开关下显示当前状态；只有操作失败及新出现的异常会弹窗，后台轮询不会重复弹出同一故障。GPU 采样失败会保留具体诊断，WSL 中命令未加入 PATH 时会尝试系统 GPU 工具路径。

训练对内存和显存要求较高。2026-09-17 已在本机 RTX 4050 Laptop（6 GB 显存）完成带校对文本的真实训练验收：SoVITS 与 GPT 各 5 轮，生成并校验成对权重，任务达到 100%。验收复用了参考音频，仅验证训练流程；尚未评估该模型的试听效果，也不保证每次训练都会改善声音。仅语音模式还需要安装本地识别模型。

## 退出和遇到问题

- **正常退出：** 停止播报，依次关闭 Windows 执行端、TTS、主服务，再在启动终端按 `Ctrl+C`，等待退出。只关闭浏览器不会停止服务。
- **启动窗口已关闭，但服务还在：** 在项目目录运行 `npm run stop`，清理完成后重新启动。
- **提示内存不足：** 关闭其他高占用程序，检查 Windows 内存及“已提交”余量，再手动启动 TTS。

安装问题看 [启动说明](launchers/README.md)，参数问题看 [配置说明](config/README.md)。报错时，服务开关旁的“查看日志位置”可以帮你找到日志。

<details>
<summary>开发与项目结构</summary>

使用 Rust 1.85+、Node.js 22.12+、npm 10+。在项目目录执行：

```bash
npm ci
npm run check
npm run build
```

主服务在 `apps/server`，网页在 `apps/desktop`。模块保持单向依赖：`application → domain`；外部适配器实现 application 的接口，跨端契约集中在 `protocol`，Windows 执行库独立于 Tauri 外壳。前端通过 `services` 访问外部能力。

文件用途见 [目录索引](DIRECTORY.md)，协作规则见 [AGENTS.md](AGENTS.md)。改动文件后运行 `npm run tree:update` 和 `npm run tree:check`；`npm run check` 已包含索引检查。自动化检查不能替代真实声音、VTS 和直播间验证，实机步骤见 [端到端验证](tests/e2e/README.md)。

`docs/` 为 Git 忽略的本地文档目录。私有配置、密钥、录音、模型和运行数据不随源码提交。可选桌面窗口见 [Tauri 说明](apps/desktop/src-tauri/README.md)。
