# Windows App 更新发布

App 固定读取 `KafuuChinoQwQ4/MeowLive2D` 的 GitHub Releases，包括 `v版本号-windows-preview.YYYYMMDD` 预览版。构建时通过 `MEOWLIVE_RELEASE_TAG` 写入实际发布标签，相同版本号的预览版按日期排序，正式版本高于同版本预览版。

发布前由仓库管理员配置：

- Actions variable `MEOWLIVE_UPDATE_PUBLIC_KEY`：Ed25519 公钥原始 32 字节的 Base64 编码。它随 App 编译，不是 secret。
- Actions secret `MEOWLIVE_UPDATE_PRIVATE_KEY`：与公钥配对的 Ed25519 PKCS#8 PEM 私钥。只提供给发布任务，不能提交进仓库或输出到日志。

发布管理员负责生成并保管签名密钥；本地备份只能放在 Git 忽略且权限受限的私有目录。缺少签名配置时仅发布手动安装包并输出警告，不生成自动更新清单；未内置公钥的 App 拒绝自动安装。配置存在但私钥、公钥不匹配时发布失败。首次启用更新需要手动安装带有正确公钥的新安装包；已有旧版本不会凭空获得自动更新能力。当前单公钥协议不支持自动轮换；更换公钥时需要用户手动安装可信的新版本。

推送发布标签后，CI 在 Windows 构建 NSIS 安装包。发布任务验证校验和，再使用 `scripts/update-manifest.mjs` 生成并上传：

- 原始 `*-setup.exe`，作为完整下载回退。
- `meowlive-update.json`，包含 Base64 原始 JSON 载荷和 Ed25519 签名；载荷固定标签、安装包名称、大小、SHA-256 和有序分块清单。
- `chunk-<SHA-256>.bin`，采用内容定义边界，块大小为 256 KiB 至 1 MiB（末块可更小），同一安装包的重复块只上传一次。文件偏移改变后可重新找到相同内容边界。

NSIS 使用 `compression: none`，避免整体压缩让微小变更扩散到全部安装包；代价是完整安装包更大。安装包受 GitHub 单文件小于 2 GiB、每次发布 1000 个资产的限制，签名生成器最多允许 990 个唯一分块，为安装包和辅助文件留出余量。上传分批进行，全部完成才公开草稿发布。

App 在专属更新缓存中保留最近安装包的分块。下一次更新逐块验证缓存，复用未改变的块，只下载缺失或损坏的块，再重建安装程序并验证整包 SHA-256。首次更新没有缓存时需要完整下载；编译后二进制变化较大时，节省量也可能很小。界面显示真实下载和复用字节数，不保证固定节省比例。分块资源不可用时回退完整安装包下载，仍验证签名指定的每块及整包摘要。

安装前再次验证文件，使用 NSIS `/UPDATE /P /R` 覆盖安装并重启。模型和配置位于独立用户数据目录，不列入更新载荷。训练或环境变更期间禁止安装，由 App 先停止受管服务。网络有大小、超时和 HTTPS 重定向来源限制；取消等待当前有超时限制的请求结束。

必须在 Windows 实机验证完整首更、下一版分块复用、网络中断重试、UAC、安装重启及模型/配置保留。Linux 单测和模拟不能代替该验收。
